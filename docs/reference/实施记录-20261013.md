## 1. 最终定位

**打开页面就进入一座小马家园，点建筑抽牌，立即得到轻松、温柔的指引。免费、无需登录、快速使用。**

场景是首页，建筑是导航，小马提供陪伴感。保留根目录 `整体参考风格.png` 的童话插画、水晶造型和小马家园气质，提供两种可切换主题：明亮主题使用原日景、奶油白与紫粉 UI；暗色主题使用星空夜景、深紫与月光金 UI。页面右上角和设置面板均可切换，浏览器记住选择，默认暗色。

按最新要求，框架直接准备完整 **78 张牌的数据与牌义**。**正式塔罗卡面由你提供**。现已接入"卡牌版本1"的全部 78 张卡面；原图保留，网页使用压缩后的 WebP。整套内容注册为独立卡组 `pony-v1`（见第 11 节），后续可继续接入新卡组。

## 5. 玩法与内容边界

### 今日一牌

首页点击甜点屋或"抽取今日牌"，再点击牌背，即得到当日固定牌、关键词、牌义和一条轻松的小行动。每日牌按访客本地日期切换；它是公共日期指引，不宣称个人专属预测。每套卡组每日固定保存一条记录，重复保存更新同一条。

### 三牌占卜

当前处境 / 可以尝试的行动 / 值得留意的方向。当前三牌流程先填写问题，保留在本次结果和记录里；每日一牌的问题选填。抽牌结果只生成一次，跳过动画不重新抽牌。

可单独翻牌或一起翻开。结果包含实际抽到的牌义、简短整理建议与可展开详情；角色切换只改变表达语气，不改变牌义。

普通抽牌不发送问题，基础模板不自动理解问题语义；仅主动点击每日或三牌AI解读才发送本次问题和牌义。界面说明"带着你的问题阅读指引"。不做必然预言，标明供娱乐与自我整理参考。

### 本地记录

保存当时的牌、问题、角色、解读、卡组归属和时间快照，最多 50 条，超出时替换最早一条。记录仅在当前浏览器，清理浏览器数据会丢失，提供文本导出（每条注明所属卡组）。无法保存时显示提示，不阻止查看结果。查看记录时展示的是保存时的内容快照，切换卡组不会改写旧记录。

## 6. 技术与源码入口

Next.js 16.4.0、React 19.3.0、TypeScript 5.9.3；样式与动画使用原生 CSS。主要交互集中在 `app/page.tsx` 一页，使用 React 状态与原生 `<dialog>`，当前不需要 Zustand、Tailwind 或额外动画库。

**运行时卡组数据的唯一来源是 `data/deck-definitions/*.json`**：构建或检查前 `scripts/sync-decks.mjs` 校验全部卡组并生成 `data/decks.generated.json`，页面经 `data/decks.ts` 读取。`data/cards.ts` 只是第一套牌的 ID 与中文名称清单，供卡面导入脚本（`cards:prepare`、`cards:sync`）和逻辑检查使用，不再是页面数据源；页面卡面路径一律以卡组配置 `cards[].image` 为准。

```text
pony-tarot/
├── app/page.tsx                  家园首页、功能入口与本地会话
├── app/layout.tsx                全局元数据与根布局
├── app/globals.css               全局样式、手机布局、动效
├── components/                   面板容器、翻牌、图鉴、记录、设置、卡组切换、图标
├── data/deck-definitions/        卡组注册源（JSON，牌义内容在此维护）
├── data/decks.generated.json     由 decks:sync 生成的运行时注册表（勿手改）
├── data/decks.ts / types.ts      运行时读取与类型定义
├── data/cards.ts                 第一套牌 ID/名称清单（脚本与校验用）
├── data/personas.ts              M6 开场与收尾话术
├── lib/engine.ts                 洗牌、每日牌、解读与记录快照
├── lib/storage.ts                本地记录及设置
├── public/art/                   网页家园素材
├── public/cards/                 第一套 78 张 WebP 卡面与 manifest.json
├── public/card-list.csv          完整牌 ID 与建议文件名
├── asset-sources/                生成源图与完整提示词
├── scripts/                     卡组校验、逻辑检查、图片扫描压缩、静态预览
├── previews/                    桌面与手机预览截图
├── 卡组接入说明.md               新卡组的配置格式与抽牌约定
└── .next/standalone/            构建后的 Node 服务部署目录
```

基础版曾使用静态导出；AI接入后已改为Node Next服务，图片仍预先压缩，图片优化关闭、保留`trailingSlash`。配置依据：[Next.js 静态导出官方文档](https://nextjs.org/docs/app/guides/static-exports)。发布平台和访问额度在正式上线时确定。

## 7. 本地启动

进入 `pony-tarot/`，依赖已经安装。继续开发：

```powershell
npm.cmd run dev
```

打开 `http://127.0.0.1:3000`。若该端口已有预览运行，直接打开即可，无需重复启动。

检查、构建并启动生产预览：

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run preview
```

开发服务和生产预览使用同一端口，运行其中一个即可。`check` 与 `build` 都会先执行 `decks:sync` 校验卡组再继续。当前运行方式为Node Next服务，须支持API、SSE与持久SQLite；旧`out/`静态产物不能提供当前AI功能。

## 8. 78 张卡面已接入与批量处理

本次原图位于根目录 `卡牌版本1/`：78 张 1024×1536 PNG，共 184.90 MiB。已按目录组别和文件前两位编号，映射至稳定牌 ID。批量生成 768×1152 WebP（quality 86），无裁切，合计 14.20 MiB，减少 92.3%；原图不改动。图鉴使用懒加载，抽牌与详情及时加载。导入对应关系和逐张体积见 `pony-tarot/asset-sources/card-import.json`。

在 `pony-tarot` 目录重复处理本套卡牌：

```powershell
npm.cmd run cards:prepare
npm.cmd run build
```

脚本 `scripts/prepare-cards.mjs` 校验 78 张完整性、编号不重复和 2:3 比例，再转换并同步映射。默认读取 `../卡牌版本1/`，构建会更新应用产物。

也可手动将网页卡面放进 `pony-tarot/public/cards/`，采用 `public/card-list.csv` 中的稳定 ID 命名。支持 `.webp`、`.png`、`.jpg`、`.jpeg`、`.avif`。

| 示例 | 卡牌 |
|---|---|
| `major-00.webp` | 愚者 |
| `major-01.webp` | 魔术师 |
| `major-21.webp` | 世界 |
| `wands-01.webp` | 权杖王牌 |
| `cups-14.webp` | 圣杯国王 |
| `swords-12.webp` | 宝剑骑士 |
| `pentacles-13.webp` | 星币王后 |

然后运行：

```powershell
npm.cmd run cards:sync
```

注意：`public/cards/manifest.json` 现在只是第一套卡面导入脚本的产物（同时生成 `card-list.csv`）。图鉴、今日一牌和三牌结果的卡面路径**以卡组配置 `cards[].image` 为准**，不再读取 manifest。因此新增卡面时，除了放对文件名，也要保证 `data/deck-definitions/pony-v1.json` 中对应牌的 `image` 指向它（第一套按稳定 ID 命名时两者天然一致，无需改动）。构建前会自动校验配置里的图片文件真实存在。

统一卡背目前是代码绘制的测试用样式。你若另有正式卡背，在卡组配置中提供 `backImage` 即可整体替换。

服务端拟发送：

```json
{
  "model": "glm-5.2",
  "messages": [
    {
      "role": "system",
      "content": "用温和清楚的中文，结合用户问题和提供的牌义解读。只使用给定牌、方向及牌位，不重新抽牌、不编造卡组设定、不作确定性预测。回应问题，解释三张牌的联系，给出一项具体小行动。"
    },
    {
      "role": "user",
      "content": "这里由服务端填入：问题、卡组名称与版本，以及三张牌各自的牌位、名称、正逆位、关键词、对应牌义和现有行动建议。"
    }
  ],
  "max_tokens": 1500,
  "temperature": 0.7,
  "stream": true,
  "stream_options": { "include_usage": true },
  "thinking": { "type": "disabled" }
}
```

`thinking` 是拟选 GLM-5.2 的待验证配置；若改用其他模型，应按其文档选择或移除，不能假定全部模型都允许关闭。流式累积 `choices[].delta.content`；`reasoning_content` 不作为解读正文展示。`stream_options.include_usage` 的支持情况在接入时验证；usage 可能位于 choices 为空的独立末尾事件，统计缺失不代表零消耗。正文为空或 `finish_reason` 表示截断时明确提示，不把不完整输出当作完整结果。

**第一版即实现流式链路**：浏览器 POST 本站 `/api/interpret`，本站服务端读取数据库中的用户 Key，再 POST 标准 Chat Completions；服务端返回 `text/event-stream`，前端通过 `fetch` 的响应流读取（原生 EventSource 不适合这里的 POST 请求）。服务端不等待整段输出才返回，部署网关也不能缓冲整段响应。

服务端解析上游 SSE，转换为本站事件：`delta`（正文增量）、`done`（完成状态与可用 usage）、`error`（脱敏后的错误原因）。按完整 SSE 事件解析 JSON，使用流式 UTF-8 解码和跨分包缓冲，支持 CRLF、多行 data、注释心跳及结束标记；不能把每块网络字节直接当作一个 JSON。结束标记、usage 与正文事件分开处理。

前端收到正文便开始显示，约每80ms合并一次更新，不做人为逐字延时。加载阶段显示“正在连接／正在解读”，提供“停止生成”。只有明确完整结束且未截断才标记完成、写入成功缓存；断流、取消或达到长度上限时保留已收到内容并标成“未完成”，不自动重试，也不把半段结果保存成完整解读。原有本地内容始终可读。

### 12.5 用户填写 Key，服务端数据库保存

设置页新增“AI 解读配置”：用户填写自己的标准 API Key（密码输入框）、模型 ID，保存、替换或删除。默认未配置，不使用作者或平台的公共 Key。

**计划使用 SQLite + 单实例 Node 服务**，作为当前最小实现路线；如果最终选择无持久磁盘或多实例托管，需改为该平台支持的持久数据库，不能使用临时文件冒充持久保存。

计划表 `model_credentials`：`id`、`owner_token_hash`、`provider`、`model`、`key_ciphertext`、`key_iv`、`key_tag`、`key_last4`、`config_revision`、创建/更新时间。唯一作用是保存当前浏览器对应访客的模型配置。

- 保留免登录基础体验。服务端设置高随机匿名凭证到 HttpOnly Cookie，生产环境使用 Secure/SameSite；数据库存其哈希。每次读、改、删及解读，都由 Cookie 确认归属，不能凭前端传入的用户ID或配置ID越权访问。
- Key 用 AES-256-GCM 等带认证加密方式保存；加密主密钥在服务器环境变量中，不与数据库存一起。返回设置只含“已配置”和尾号，不回传完整 Key。
- 前端不把 Key 放进 localStorage、IndexedDB、URL、聊天记录、构建包或日志；用户提交时通过 HTTPS 发给本站服务端，随后仅服务端解密调用智谱。
- 配置写操作需要同源/CSRF检查。第一版固定提供方和标准端点，不接收任意用户 URL，避免把服务端变成公开代理。
- 无需注册账号。更换浏览器或清 Cookie 后不能认领原配置，需要重新填写。提供删除按钮；无人使用的旧匿名配置按约定保留期清理（建议30天），以免数据库永久积累 Key。
- 普通抽牌、图鉴和本地记录不要求填写 Key。网站基础功能免费；AI 请求使用用户自己的标准 API 额度，按提供方规则计费，配置处应说明。

真实 Key 不进入本文或源码。本次收到的 Key 不用于代替用户配置，也未验证它属于哪种套餐或具有什么权限。

### 12.6 只调用一次、失败仍然能用

- 默认关闭，用户主动点击后才发送问题与当前牌义；按钮旁明确说明数据将经本站服务器送至智谱。
- 同一次结果请求中禁用重复点击；取消/关闭面板时可中止等待，不保证已经发往上游的请求不计费。
- 以访客身份 + 问题 + 卡组内容版本 + 牌/方向/牌位 + 模型配置版本 + Prompt版本构建指纹，复用已经完成的同次解读。角色切换、页面渲染和查看记录不重新调用；改变问题会构成新请求。
- 每访客限制同时1个请求，建议每小时最多10次实际模型请求；服务端执行。第一版不做自动重试，超时/429/认证错误显示简短原因，用户主动决定是否重试。
- 流式起始配置：连接／首个模型事件最多45秒，模型事件空闲最多30秒，整个请求最多120秒；收到有效模型事件刷新空闲计时，代理心跳不掩盖上游卡住。用户停止或关闭面板时，浏览器和服务端向上游传播取消信号；部署超时不得短于约定的请求时限。只发送本次问题与三张牌的文字，不发送所有历史、整个牌库、卡面图片或 Key 到 Prompt。
- 本地解读始终保留。AI 成功后在独立区块展示并可随记录保存，记录区分本地内容与AI内容；不覆盖卡组标准牌义。保存 AI 完整文本、模型实际返回标识和时间快照，后续切换卡组不改写。

公网HTTP复现了第二个原因：`crypto.randomUUID()`在非安全上下文不可用，三张牌虽翻开，创建reading记录却抛错，因而没有AI区域。本轮改用`crypto.getRandomValues()`生成128位记录ID，保持每日ID规则与已有记录兼容，并新增仅提供getRandomValues的回归检查。API上下文区别见[MDN randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)与[getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)。

类型/逻辑检查、生产构建通过；部署前后首页与16项实际资源/API检查通过。公网真实浏览器完成问题输入、三牌翻开、小马AI入口与手机跳转，六枚透明SVG显示正常。本轮没有向模型提供方发起真实生成请求，也没有消耗用户额度；新访客未配置Key时显示原位设置入口。
