# 小马塔罗 · GLM AI 解读接入方案

定稿：2026-10-13。本文档是《最终计划.md》第 12 节的实施设计稿：第 12 节记录端点实测与社区调研，本文档回答"加在哪、长什么样、代码怎么落、怎么验收"。实施完成后将实施结果回写《最终计划.md》。

## 1. 定位与三条底线

AI 是**表达层增强**：把本地牌义改写成贴合提问的个性化文案。三条底线不动摇：

1. **抽牌本地确定**——日期哈希、Fisher–Yates 洗牌、正逆位判定全部留在 `lib/engine.ts`，AI 不参与、不感知抽牌过程；
2. **本地解读永远先行**——AI 文本是追加块，不是替换品；断网、超时、没配 Key，网站行为与现在完全一致；
3. **默认关闭、显式开启**——用户在设置页主动开启并填入自己的 Key（BYOK），点按钮那一刻问题与牌义才会离开浏览器。

## 2. 入口分析：为什么只加在结果区

| 候选位置 | 价值 | 成本/风险 | 结论 |
|---|---|---|---|
| 解读结果区：结合问题改写牌义 | ★★★ 个性化价值最大，本地解读兜底 | 低，一个按钮 | **P1 实施** |
| 追问对话：针对结果继续提问 | ★★ 参考项目验证过吸引力 | 多轮上下文、聊天 UI、按轮计费 | P2 |
| 图鉴详情页提问 | ★ 缺阅读上下文 | 中 | 暂不做 |
| 手札历史总结 | ★ 需整批发送隐私记录，违背最小发送 | 高 | 不做 |
| 抽牌过程介入（改问题/影响抽牌） | 0 | 违背底线 1 | 永不 |

甜点屋（每日一牌）与紫悦城堡（三牌占卜）共用 `ReadingPanel` 组件，结果区加一处即两处覆盖。每日一牌无问题输入，个性化价值较低，但零额外成本，一并覆盖。

## 3. UI 设计

### 结果区（ReadingPanel）

现有结构自上而下：标题 → 角色选择 → 角色开场白 → 每张牌折叠解读 →（三牌）综合提示 → 小行动 → 角色收尾 → 操作按钮排（保存 / 再抽一次）→ 状态消息。

新增两处：

- **按钮**：加进操作按钮排，次要按钮样式，文案"✧ AI 个性化解读"。规则：
  - 未开启 AI 或未填 Key → 点击提示"先去设置页添加你的智谱 API Key"，并附跳转设置的链接；
  - 生成中 → 按钮变为"星光正在汇聚…"并禁用，可点击"停止"中断（AbortController）；
  - 已生成 → 按钮文案变"重新生成"。
- **AI 展示区**：操作按钮排下方新块，默认不可见。生成时流式填充；完成后顶部显示小字"由 {model} 生成 · 仅供娱乐与自我整理参考"，右上角"重新生成"。折叠态收起时保留"AI 解读已生成"摘要行。

本地解读的所有元素原地保留，不因 AI 生成而隐藏或替换。

### 设置页（SettingsPanel）

新增"AI 个性化解读"区块，置于卡组选择之后：

- 总开关（默认关）；关闭时其余输入禁用；
- 端点预设：下拉二选一——"智谱 Coding 订阅"（默认端点 `/api/coding/paas/v4`、默认模型 `GLM-5.2`）与"智谱标准按量"（`/api/paas/v4`、默认模型 `glm-4-flash`）；选择预设自动填充端点与模型；
- 模型名：文本框，可手改（响应 model 字段与请求别名可能不一致，不做校验）；
- API Key：password 输入框，下方固定小字"仅保存在这台设备的浏览器里"；
- 隐私说明："开启并点击 AI 解读后，你填写的问题与抽到的牌义会发送至智谱 API 生成文案。关闭即恢复纯本地解读。"

## 4. 代码落点

```text
lib/ai.ts                    【新建·核心】
  - buildPrompt(kind, draws, question, persona, deck)   组装 system/user
  - streamCompletion(config, messages, callbacks)        直连 bigmodel，
    fetch + SSE 解析 + 双超时 + 80ms 回调节流 + AbortController
  - classifyAiError(err)                                 错误分类（见 §7）
  - prompt 事实层只含本地数据：牌名/正逆位/关键词/牌义
lib/storage.ts               settings 增加 ai 字段；Key 另用独立 storage key
                             'pony-tarot-ai-v1' 存（与普通设置隔离，便于单独清除）
data/types.ts                AiConfig { enabled, preset, endpoint, model, key }
components/SettingsPanel.tsx AI 设置区块
components/ReadingPanel.tsx  按钮 + AI 展示区 + 状态机 idle/streaming/done/error
app/globals.css              AI 区块样式（沿用深紫金边，新增流式光标闪烁）
```

数据流（单向）：

```text
本地抽牌(engine.ts, 不动) → 本地解读(先显示) → 用户点按钮
  → lib/ai.ts 组装 prompt → 直连智谱(浏览器 CORS 已实测放行)
  → 流式写入展示区 → 按阅读 ID 缓存 localStorage
  → 任何失败 → 保留本地解读 + 中文错误提示
```

缓存规则：key = `ai:{readingId}`，命中直接展示不重发；"重新生成"绕过缓存并覆盖。Key 校验失败（401/403）时缓存不写入。

## 5. 接口与请求细节（已实测，2026-10-12）

OpenAI 兼容 Chat Completions，`POST` + JSON，`Authorization: Bearer <Key>`：

| 端点 | 适用 | 默认模型 | 实测 |
|---|---|---|---|
| `https://open.bigmodel.cn/api/coding/paas/v4/chat/completions` | Coding 订阅 Key | `GLM-5.2` | 200（响应报 glm-5.3） |
| `https://open.bigmodel.cn/api/paas/v4/chat/completions` | 标准按量 Key | `glm-4-flash`（免费档） | 200 |

- 两个端点浏览器 CORS 预检均放行（含 authorization 头），纯静态直连成立，无需任何代理；
- **必须带 `"thinking": {"type": "disabled"}`**，否则推理消耗 max_tokens 致正文 0 字（实测关闭后 reasoning_tokens: 0）；
- `max_tokens ≥ 1500` 防截断；`temperature` 0.7；超时：连接 20 秒、流空闲 60 秒；
- 第一版即上流式（`stream: true`，SSE 解析 `delta.content`）；思考字段按 `reasoning_content` / `reasoning` / `thinking` 多键兼容解析（虽然默认已禁思考）；
- 结束读 `usage` 存入缓存记录（展示"本次消耗 {total_tokens} tokens"小字，帮用户建立成本感知）。

## 6. Prompt 设计草案

**System（两种 kind 共用，注入角色语气）：**

```text
你是小马镇塔罗解读师「{persona.name}」。你的说话风格：{persona.intro}{persona.closing}

规则（必须遵守）：
1. 只基于【给出的牌义与关键词】发挥，不新增牌义，不改变正逆位方向；
2. 不做确定性预测，不承诺结果；不给医疗、法律、投资建议；
3. 定位是帮助对方整理想法的温柔参考，供娱乐；
4. 全程中文，语气温和轻松，符合角色说话风格，不堆砌神秘学术语。
```

**User · 三牌占卜：**

```text
问卜者的问题（选填）：{question 或 "没有填写问题，请按通用情境解读"}
抽到的牌：
【当前处境】{nameCn}（{正位|逆位}）
- 关键词：{keywords}
- 牌义：{meaning}
【可以尝试的行动】…
【值得留意的方向】…

请写这次占卜的个性化解读：每张牌一段（以"牌位·牌名"开头，结合上面的问题
谈这张牌想表达什么），最后一段给整体建议（从"可以尝试的行动"位切入）。
总共不超过 400 字。
```

**User · 每日一牌：**

```text
今天是 {YYYY年M月D日}。今日牌：{nameCn}（{正位|逆位}）
- 关键词：{keywords}
- 牌义：{meaning}

请写今日指引：先用 1-2 句描绘今日能量基调，再结合"今日"的语境解释这张牌
（不要复述牌义），最后给 2-3 条具体的今日小建议。总共不超过 300 字。
```

## 7. 错误处理与降级

| 情形 | 行为 |
|---|---|
| 401 / 403 | "Key 无效或无权限，请到设置页检查" ；不写缓存 |
| 404 | "模型名不存在，请检查模型设置" |
| 429 | "请求太频繁，稍后再试"，30 秒内禁用按钮 |
| 超时 / 网络错误 | 自动重试 1 次（指数退避 2 秒），再失败提示并保留本地解读 |
| 流中断（已有部分正文） | 不报错，直接展示已有内容，尾部加"（传输中断，内容可能不完整）" |
| 用户停止 | AbortController 中止；已有内容保留 |
| 生成失败任意情形 | 本地解读全程可见，AI 区块显示错误 + "重试"按钮 |

错误文案不含原始报错与 Key 片段（参考 TarotWhisper 的脱敏规则）。

## 8. 安全与隐私清单

- Key 仅存 localStorage（独立 storage key），不进代码、文档、Git、构建产物；
- 项目初始化 Git 时 `.gitignore` 首条排除 `.env*`；作者的真实 Key 只用于本地测试，不共享；
- 发送内容最小化：仅问题（≤200 字，已有上限）+ 抽中牌的名称/方向/关键词/牌义，不含用户记录、浏览器信息；
- 设置页与 AI 展示区双处隐私说明；页脚"非官方粉丝作品"不变；
- `THIRD_PARTY_LICENSES.txt` 增加 AI 服务条目：数据发送至智谱开放平台处理，适用其服务条款与隐私政策。

## 9. P1 实施清单与验收

按顺序实施（改动文件见 §4）：

1. `data/types.ts` + `lib/storage.ts`：AiConfig 读写、预设档默认值、设置持久化回归；
2. `lib/ai.ts`：prompt 组装、SSE 流式请求、错误分类（含对 `thinking` 字段与多键思考字段的单元断言，可加入 `scripts/check.ts` 的纯逻辑部分——mock fetch，不发真请求）；
3. `SettingsPanel.tsx`：AI 区块；
4. `ReadingPanel.tsx`：按钮、状态机、展示区、缓存；
5. `globals.css` 样式；
6. 文案回写：《最终计划.md》§5 边界表述、§12 实施记录、页脚/隐私文案、`THIRD_PARTY_LICENSES.txt`。

验收标准：

- [ ] 未配置：点按钮出现引导文案，可跳转设置；
- [ ] 配置后：点按钮流式出字，完成后有模型名与 token 消耗标注；
- [ ] 断网/拔 Key/改错模型名：分别得到对应中文提示，本地解读不受影响；
- [ ] 生成中点"停止"：立即中止，已有内容保留；
- [ ] 缓存：同一阅读重复点击不发新请求，"重新生成"会重发并覆盖；
- [ ] 回归：抽牌、保存、图鉴、记录、主题、动效开关全部正常；`npm.cmd run check` 与 `npm.cmd run build` 通过；
- [ ] 全流程断开 AI（清 localStorage）后网站行为与上线前版本一致。

## 10. P2 及以后（本期不做）

- **追问**：结果区下方开对话输入，复用 `lib/ai.ts`；首期不做"补抽牌"决策步，仅基于已抽牌直答；
- 流式打字机光标、按牌阵扩展 prompt、多卡组 prompt 适配（`custom` 卡组无逆位时自动去掉方位描述）；
- 服务端代理方案（无 Key 访客兜底 + IP 限流）：仅在产品需要"全员开箱即用"时启动，蓝本为 TarotWhisper `app/api/interpret/route.ts`。
