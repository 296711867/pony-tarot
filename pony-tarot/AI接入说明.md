# AI 解读使用与部署

已接入智谱**标准 API**：`https://open.bigmodel.cn/api/paas/v4/chat/completions`，默认模型 `glm-5.2`。模型权限与账户额度需使用你自己的标准 API Key 确认；Coding Plan 的订阅额度不用于本站。

## 使用

打开小镇设置，在“模型配置”中填写自己的 Key 和模型 ID，勾选“开启 AI 解读”并保存。“模型配置”设有管理密码门（2026-10-15 加入）：输入正确密码后本次浏览会话内保持解锁，关闭浏览器后重新上锁；占卜结果页的原位设置入口同样受此保护。进入三牌占卜，填写问题并翻开牌，选择小马后点击“请XX解读”。今日一牌翻开后也可选择小马解读，问题可选。

正文以 SSE 逐步显示，可停止生成。只有完整结果进入成功缓存并可随记录保存；断流、取消或长度截断都会显示“未完成”。角色切换不重抽、不自动请求；每位小马有独立语气Prompt和缓存，选择后手动点击才生成。相同问题、牌和角色的完整结果可复用。图鉴与基础牌义仍本地运行。

Key 用 AES-256-GCM 加密保存到服务器 SQLite；浏览器只保留匿名身份 Cookie，设置页只显示 Key 尾号。清 Cookie 或换浏览器后需要重新填写。删除 Key 会清除该身份的配置和成功缓存。数据库在活动时每小时清理一次：30天未访问的配置、7天前的缓存及过期调用计数。

AI 使用你自己的账户额度，网站不提供公共兜底 Key。点击时，只发送本次问题、卡组名、当前牌与对应牌义，不上传历史记录或图片。

## 本机启动

需要支持 `node:sqlite` 的 Node（本机为22.23.2）。第一次部署：

```powershell
npm.cmd run ai:setup
npm.cmd run build
npm.cmd run preview
```

开发使用 `npm.cmd run dev`。当前生产预览为 `http://127.0.0.1:3000/`。不再使用旧的 `out/` 静态文件夹或 `scripts/serve.mjs` 启动新功能。

`ai:setup` 只生成服务器数据库加密主密钥，写入 `.env.local`，不生成或填入用户的模型 Key；已有主密钥不会被覆盖。该文件和 `.runtime/` 已加入忽略规则。不要丢失主密钥：数据库密文需要原主密钥才能解密。

## 部署

完整发布步骤见同目录`部署说明.md`。当前已启用standalone输出；运行`npm run build`后执行`npm run deploy:prepare`补齐静态资源，独立目录通过`node server.js`启动。数据库与加密主密钥单独配置，不能只复制应用就期望原用户配置一并迁移。

使用单实例 Node Next 服务和持久磁盘；默认数据库为 `.runtime/pony-tarot.sqlite`。生产环境设置：

- `MODEL_ENCRYPTION_KEY`：64位十六进制随机主密钥，安全保留，不能随意更换。
- `MODEL_DB_PATH`：可选，指定持久数据库路径。
- `APP_ORIGIN`：生产网站的准确 HTTPS origin，例如 `https://your-site.example`，不能带末尾斜杠。用于同源写请求检查及 Secure Cookie；反向代理部署必须正确设置。

网关关闭响应缓冲、允许 SSE 长连接，超时至少150秒；客户端模型请求总时限120秒，首个模型事件45秒、事件空闲30秒。代理心跳不重置模型空闲计时。SQLite 文件、WAL 与主密钥必须按一致备份方案保留。不能把数据库放在无持久存储的临时 serverless 文件系统中。

`/api/model-config/` 用于当前访客的脱敏配置查询、保存和删除；`/api/interpret/` 是统一的每日/三牌模型调用。每访客同时1个请求，每小时最多10次实际请求；失败请求也消耗调用次数，不自动重试。同一身份、问题、角色、实际牌义及模型配置的完整结果可复用。

## 验证

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd run check:ai
```

`check:ai` 启动3097端口的临时测试服务，使用系统临时目录中的独立数据库及明确无效的测试 Key，通过预加载脚本在服务端拦截模型请求。不会访问真实提供方。检查：访客隔离、同源校验、数据库密文、分包中文、多行/注释SSE、usage独立事件、缓存与角色复用、流截断、并发与取消、错误脱敏、删除配置。完成后停止测试进程并清理其临时目录。

模拟测试不证明真实 Key、额度或模型权限可用。最初模拟检查未使用真实Key。之后按用户明确要求配置了其Key，修复127.0.0.1与Next内部localhost不一致导致的来源误判，并通过一次真实标准API流式解读。其他用户仍在设置页填写自己的Key；错误显示在AI区块，基础结果保持可用。
