# 发布准备与上线步骤

当前是单实例Node Next应用，包含SQLite与SSE接口。已部署于`http://43.142.102.75:3100/`，Ubuntu 24.04、Node v22.20.0；域名与HTTPS待配置。现有主机的路径与维护命令见根目录`服务器维护.md`。

## 1. 构建与准备目录

在`pony-tarot`目录运行：

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run build
npm.cmd run check:ai
npm.cmd run deploy:prepare
npm.cmd run deploy:package
```

配置已经使用`output: standalone`。最后一步把`public/`和`.next/static/`复制进`.next/standalone/`，否则独立服务会缺少卡面、背景、字体和前端资源。可部署目录是`.next/standalone/`，其中入口为`server.js`。再次修改代码或卡组后重新构建并准备目录。

使用支持`node:sqlite`的Node版本（本机22.23.2，当前服务器22.20.0已验证）。一般优先在目标系统构建；当前standalone包含sharp的WASM回退，已经在实际Ubuntu主机通过启动和资源验收，使用bsdtar打包以避免ZIP反斜杠路径。完整项目仍可用`npm run preview`本地预览；当前发布包通过`node start.mjs`读取同目录.env后启动server.js，外部环境变量优先。

## 2. 环境与持久数据

环境变量由部署平台或服务管理器设置，不把用户Key放进源码。现有用户配置要迁移时，数据库和原加密主密钥须一起保留；新安装才生成新的主密钥。

| 变量 | 配置 |
|---|---|
| `MODEL_ENCRYPTION_KEY` | 原64位十六进制主密钥；新安装可运行`npm run ai:setup`生成后通过服务器环境安全配置 |
| `MODEL_DB_PATH` | 指向发布目录以外的持久数据库绝对路径，例如`C:\PonyData\pony-tarot.sqlite` |
| `APP_ORIGIN` | 实际网站origin，例如`https://tarot.example.com`，替换为真实域名 |
| `HOSTNAME` | 反向代理在本机时为`127.0.0.1`；托管容器按平台要求设置 |
| `PORT` | 后端监听端口，例如`3000` |

切换发布版本不能删除持久目录或更换加密主密钥。不要上传本机`.env.local`、`.runtime/`或模拟测试脚本作为公开素材。独立目录默认不含本机数据库及`.env.local`，环境必须单独注入。

## 3. 启动

在部署服务中设置上表环境，再从独立目录运行：

```powershell
node server.js
```

配置服务管理器在进程退出或主机重启后启动服务。保留单实例，避免把同一SQLite当作多主机共享存储。

当前腾讯云服务器由systemd运行`/usr/local/bin/node22 start.mjs`，应用目录的.env是指向`/home/ubuntu/pony-tarot-data/.env`的链接，数据库位于该独立目录下的`runtime/`。重复部署沿用原主密钥，禁止重新生成覆盖。

## 4. 域名与流式代理

域名通过HTTPS访问Node服务。若使用Nginx，在实际HTTPS站点的`location /`中配置以下内容；证书与域名按选定主机设置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 150s;
    proxy_send_timeout 150s;
}
```

其他网关同样需要关闭SSE缓冲并允许至少150秒的连接。设置`APP_ORIGIN`为浏览器实际访问的HTTPS origin，避免合法请求被来源检查拒绝。不能只把旧`out/`上传到静态托管平台。

## 5. 上线验收

- 首页日景/夜景、卡面、字体、图标和分享图均可访问，手机入口位置正常。
- 不配置AI也能完成每日牌、三牌、图鉴与保存回看。
- 用户在设置里填写自己的标准API Key；配置页只显示脱敏状态。
- 用一次普通问题确认真实权限及额度；正文逐步显示，停止或退出后取消请求。
- 同一内容复用完整解读；切换小马不自动调用，主动解读后角色正确。
- 重启服务后用户配置仍可读取；保存记录刷新后仍在原浏览器。
- 分享图URL使用实际域名，浏览器没有资源404或接口来源错误。

记录保存在访客浏览器，服务器数据库不包含这些历史记录；备份数据库不能替代用户导出记录。

## 6. 备份与更新

在维护窗口停止服务，再备份数据库所在目录（含存在的WAL/SHM文件）和原加密主密钥到受控位置。恢复时先停止服务，恢复完整备份并配置原主密钥，再启动验证。备份不放在`public/`内。

更新时先保存上一版应用目录，再准备新构建；持久数据库路径与主密钥沿用。服务重启后按第5节复核。新卡面使用版本路径，保留旧记录引用的图片；需要回滚时恢复上一版应用目录。
