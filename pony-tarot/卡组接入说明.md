# 接入独立卡组

当前已完成一套：`pony-v1`（小马宝莉塔罗·版本1，78张，支持逆位）。后续牌组可以有不同数量、名称、牌义、画风、卡面和卡背；内容由你提供。不要求沿用标准塔罗牌ID。

用户交付可直接填写同目录的`卡组交付模板.md`，无需写JSON。每张图片必须能与一条名称/解读对应，张数按实际提供内容决定。

## 文件怎么放

1. 卡面放 `public/decks/<卡组ID>/`，推荐网页使用等比例 WebP。卡背也放这里。
2. 在 `data/deck-definitions/` 新增独立 JSON 文件；不要改其他卡组文件。
3. 运行 `npm.cmd run decks:sync` 校验并生成注册表，再 `npm.cmd run build`。设置页会自动列出新卡组，选择会保存到当前浏览器。

本库当前有旧版 `public/cards/manifest.json`，供第一套卡面的导入脚本使用；页面运行以卡组配置中的 `cards[].image` 为准。`cards:prepare` 仍专门处理当前“卡牌版本1”，不用于推断其他卡组的名字和牌义。

## 独立卡组配置示例

以下是格式说明，不是已经安装的卡组。对应图片需由你提供。

```json
{
  "id": "forest-oracle",
  "name": "森林指引",
  "description": "一套独立的自然主题指引牌。",
  "system": "custom",
  "supportsReversed": false,
  "backImage": "/decks/forest-oracle/back.webp",
  "cards": [
    {
      "id": "seed",
      "nameCn": "种子",
      "image": "/decks/forest-oracle/seed.webp",
      "keywords": { "upright": ["开始", "耐心"] },
      "meaning": { "upright": "这里填你提供的这张牌的解读。" },
      "action": { "upright": "这里填可尝试的具体小行动。" },
      "reflection": { "upright": "这里填留给使用者的思考问题。" }
    }
  ]
}
```

- `id`：卡组用小写字母、数字与连字符，必须唯一；牌ID仅需在同一卡组内唯一。
- `cards`：非空，长度决定实际张数。每张至少提供ID、中文名称、图片、正位关键词和解读。
- `system`：`tarot` 使用标准牌类筛选和塔罗简介；其他牌组用 `custom`，不套标准塔罗分类。
- `supportsReversed`：开启时，每张必须提供 `meaning.reversed` 和 `keywords.reversed`；建议也给出逆位 `action` 和 `reflection`。关闭时不出现逆位选项，也不会抽到逆位。
- `backImage`：可选。提供时用本套图片；没有时使用带本套名称的代码卡背。
- `action` / `reflection`：可选，没有时使用明确的通用引导，不自动编造卡组专属牌义。
- `name`（外文名）、`number`（排序号）、`type`：可省略。导入时分别采用中文名、数组位置与 `custom`。标准塔罗需要按既有配置填写 `major/minor` 和 `suit`。
- 图片路径指向 `public/` 下的本地文件。文件缺失或牌ID重复会阻止构建，错误不会静默跳过。

没有逆位的卡组，页面中的“正位”只是默认方向，不表示这套牌被强行加上塔罗体系。

## 抽牌和记录的约定

- 今日一牌按本地日期和卡组固定，始终默认方向；同一天重开或切换陪伴角色不会重抽。
- 三牌从当前卡组洗牌后抽取，不放回、无重复；牌位保留“当前处境／可以尝试的行动／值得留意的方向”。少于3张的卡组使用单牌功能，不能硬凑三张。
- 支持逆位且用户开启时，每张独立以50%概率决定方向。使用浏览器随机源；牌义是本地内容，不按问题推断或操控抽牌结果。
- 每张展示自己的关键词、方向对应牌义、行动建议和思考问题；三牌整体提示根据实际牌与牌位组合，作为自我整理视角。
- 切换小马时已抽牌、牌位、方向不变；本地语气随角色切换，旧AI清除，新角色解读由用户主动点击；角色有独立Prompt与缓存。
- 保存卡组ID/名称、抽到的牌和解读快照；后续切换或修改卡组不改写旧记录。旧版本记录仍可读取，并按第一套显示归属。
- 每套每日指引每天保存一条，重复保存更新同条；三牌每次新抽单独生成记录。

你后续交付图片、名称、解读及逆位规则后，再按该套实际内容制作配置和压缩脚本。不要用第一套的编号映射去猜新卡组。

更新已发布卡面时用版本目录或新文件名，并保留已有记录引用的旧文件。记录保存文字和图片路径快照，不把图片文件嵌入浏览器；直接覆盖同一路径的图片仍会改变旧记录的画面。删除旧卡组前须确认其旧图片仍可访问。
